```
## THE SCORING PIPELINE

Implement this exactly. This is the core logic of the application.

### Data loading

On startup, load all mock data files from `/data/`. The pipeline uses:
- `actions_api_mock_v2.json` → action catalog (155 actions)
- `actions_legal_api_mock.json` → legal requirements per action
- `actions_policy_signals_api_mock.json` → policy signals per action
- `city_api_mock.json` → city context data
- `cities_api_mock.json` → city list for search

### API endpoint
```
POST /api/prioritize
Request body matches PrioritizerRequestData from prioritizer_request_mock.json:
json{
  "locode": "CL IQQ",
  "countryCode": "CL",
  "populationSize": 214857,
  "weightsOverride": {"impact": 0.5, "alignment": 0.3, "feasibility": 0.2},
  "cityStrategicPreferenceSectors": ["transportation"],
  "cityStrategicPreferenceOther": "...",
  "excludedActionsFreeText": "...",
  "cityEmissionsData": { "inventoryYear": 2022, "gpcData": {...} }
}
Step 1 — Derive city emissions by GPC ref
Sum totalEmissions for all activities within each GPC ref key from cityEmissionsData.gpcData. Skip entries with notationKey of "IE" (included elsewhere) or "NE" (not estimated). Build a dict: {gpc_ref: total_tco2e}.
Calculate total_city_emissions = sum of all GPC ref values.
Step 2 — Hard filter
Load legal requirements from actions_legal_api_mock.json.
For each action:

Get its requirements list
Check each requirement where strength is "mandatory" or "required"
If any such requirement has alignment_status = "not_aligned" → DISCARD the action (reason: legal_hard_requirement_failed)
"no_evidence" on a mandatory/required requirement does NOT discard — action passes with a flag
Actions with no legal requirements pass automatically

Return: list of valid action IDs + list of discarded action IDs with reasons.
Step 3 — Impact scoring
For each valid action, load its emissions data from actions_api_mock_v2.json.
Each action has gpcReferenceNumbers (list of GPC refs it addresses) and emissions.impactText (very_low / low / medium / high / very_high).
Impact text multiplier:
pythonIMPACT_MULTIPLIER = {
    "very_low": 0.2, "low": 0.4, "medium": 0.6, "high": 0.8, "very_high": 1.0
}
Reduction share:
pythonmatched_emissions = sum(city_emissions[ref] for ref in action.gpcReferenceNumbers if ref in city_emissions)
reduction_share = (matched_emissions * impact_multiplier) / total_city_emissions
Timeline score:
pythonTIMELINE_SCORE = {"<5_years": 1.0, "5-10_years": 0.5, ">10_years": 0.0, None: 0.0}
Impact block score:
pythonimpact_score = (0.80 * reduction_share) + (0.20 * timeline_score)
Step 4 — Alignment scoring
Load policy signals from actions_policy_signals_api_mock.json.
Formula:
pythonalignment_score = (0.80 * policy_component) + (0.15 * sector_component) + (0.05 * other_component)
Policy component: Use policy_support_score from the policy signals data (0–1 value already computed per action). If action has no policy signals, use 0.0.
Sector component: 1.0 if any of the action's sectors matches cityStrategicPreferenceSectors, else 0.0.
Other component: 0.0 (placeholder — not yet implemented, leave as 0).
Step 5 — Feasibility scoring
Formula:
pythonfeasibility_score = (0.50 * soft_legal_component) + (0.50 * socioeconomic_component)
Soft legal component:
From the action's legal requirements, take only requirements where strength is "recommended" or "optional". Score each:

aligns → 1.0
not_aligned → 0.0
no_evidence → 0.5

Average across all soft requirements. If no soft requirements → 0.0.
Socioeconomic component:
Apply the indicator key mapping first (see Page 4 bug fix above).
Each action in actions_api_mock_v2.json has socioeconomicIndicatorFit — a list of rules with indicatorKey, direction (supportive / constraining), weight, and city indicator bucket thresholds.
Bucket to score mapping:
pythonBUCKET_SCORE = {"very_low": -2, "low": -1, "medium": 0, "high": 1, "very_high": 2}
For each rule:

Look up city_indicators[indicatorKey] → get attribute_category → convert to bucket score
If direction is constraining, reverse the sign
Multiply by rule weight
Sum contributions, divide by sum of weights
Normalise to 0–1: (average + 2) / 4

If no rules match → default to 0.5 (neutral).
Step 6 — Final scoring
pythonfinal_score = (impact_score * weight_impact) + (alignment_score * weight_alignment) + (feasibility_score * weight_feasibility)
```

Use weights from `weightsOverride` if provided, else defaults (0.55 / 0.22 / 0.23). Validate weights sum to 1.0.

Sort all valid actions by `final_score` descending. Take top N (default 20).

Return full evidence breakdown for each ranked action including all sub-scores and the inputs that produced them.
```

KNOWN BUGS TO AVOID

Indicator key mismatch — city uses transport_logistics_employment, actions use employment_in_transport_and_logistics. Apply the key mapping dict in feasibility.py before any lookup. Without this fix, all socioeconomic scores will be wrong.
Sparse legal coverage — only 10 of 155 actions have legal requirements. This means soft_legal_component will be 0.0 for most actions. This is expected given the mock data — do not treat it as a bug. The feasibility score for most actions will be driven entirely by the socioeconomic component.
Explanation field — every ranked action must have an explanation field in the API response. Populate it with a human-readable string:

pythonexplanation = f"Ranked #{rank} with a final score of {final_score:.2f}. Impact: {impact_score:.2f} (reduction share: {reduction_share:.1%}). Alignment: {alignment_score:.2f} (policy support: {policy_component:.2f}, sector match: {'yes' if sector_component else 'no'}). Feasibility: {feasibility_score:.2f}."
```

4. **Timeline 0.0 floor** — actions with timeline > 10 years or unknown get 0.0 timeline score. This is intentional but means long-term structural actions are penalised. This is by design in the current model.

5. **notationKey filtering** — when summing city emissions, skip GPC refs where `notationKey` is `"IE"` (included elsewhere) or `"NE"` (not estimated). Including them would double-count or inflate the total.
```
